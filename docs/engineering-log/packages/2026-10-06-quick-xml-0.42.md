# `quick-xml` 0.41 → 0.42 (2026-10-06)

Backlog item (`2026-10-06-major-version-backlog.md`). One crate declares
`quick-xml`: `talos-worker-runtime`, for the `xml_to_json` host function
modules call on text they fetched, and for decoding the entities in an
object-storage listing.

## What 0.42 changed

The reader's events are text (`str`), no longer bytes: an element name is a
`&str`, and `BytesText` / `BytesRef` have no `decode()` — the event
dereferences to the text as it appeared in the source. Four lines of
`xml_string_to_json` changed. The one failure path that disappeared
(a decode error on text) could not occur: the reader is built from a `&str`.

## Verified: the output is unchanged

Before the bump, the converter's result for thirty edge-case documents was
recorded under 0.41 and frozen as
`xml_to_json_output_is_unchanged_for_the_recorded_corpus`
(`worker/tests/sandbox_security_tests.rs`): line endings, CDATA, attributes,
namespace prefixes, mixed content, numeric and predefined entities, invalid
and unterminated entities, comments and processing instructions inside text,
a byte-order mark, repeated elements, two roots, trailing text, truncated and
mismatched documents. All thirty rows are identical under 0.42.

The table records behaviour, not a design: CDATA and attributes are dropped,
a repeated element keeps its last value and a second root replaces the first.
Those are the converter's choices, unchanged here.

A second new test pins that an entity the document declares in its own DTD is
never expanded (`xml_internal_entities_are_refused_not_expanded`): the
existing external-entity test accepts either a refusal or a non-expansion,
and nothing covered the nested-declaration ("billion laughs") shape.

`sandbox_security_tests` 39 pass; `talos-worker-runtime` 900 unit tests pass
under nextest (they include the object-storage entity decoder's).

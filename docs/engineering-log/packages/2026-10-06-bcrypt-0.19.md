# `bcrypt` 0.18 → 0.19 (2026-10-06)

Backlog item, first of the authentication group
(`2026-10-06-major-version-backlog.md`). bcrypt stores user passwords, API
keys, MCP agent tokens, refresh tokens and two-factor backup codes; ten
crates inherit it from the workspace table, so the bump is one line.

## Measured

A throwaway harness linked 0.18.0 and 0.19.3 side by side:

* **Hashing and verifying across the versions** — 12 inputs (empty, short,
  non-ASCII, 71/72/73/100/200 bytes, an embedded NUL, 64 and 128 hex
  characters): a hash made by either verifies with the other, and the same
  wrong inputs are refused by both.
* **Stored-hash shapes** — 16 (empty, truncated, one character short or long,
  the `$2a$` / `$2y$` / `$2x$` prefixes, a non-bcrypt prefix, costs 3 and 32,
  a non-numeric cost, a bad base64 character, plaintext, surrounding
  whitespace, the OpenBSD reference vector): the same verdict from both.
* **Costs** 0, 3, 4, 5, 32, 99: the same from both. `DEFAULT_COST` is 12 in
  both.

The only differences are the WORDING of eight `InvalidHash` errors
("the hash format is malformed" gained "; expected 60 ASCII bytes"). No code
in the workspace reads that text.

Both versions ignore everything after the 72nd byte, as bcrypt does. The
callers already account for it: a password longer than 72 bytes is refused
at validation, and an MCP agent token (74 characters) is looked up by the
SHA-256 of the whole token before bcrypt is asked about its first 72.

## Changed

* `bcrypt = "0.19"` in the workspace table. Lockfile: `bcrypt` and
  `blowfish` move; `cipher` 0.5.2 and `inout` 0.2.2 arrive beside the 0.4 /
  0.1 copies the current `aes-gcm` uses. They are the next generation of the
  same trait crates and become the only copies when the encryption family
  moves.
* `a_hash_written_by_an_older_bcrypt_still_verifies` (`talos-auth`): three
  hashes produced by 0.18.0 from made-up passwords and the OpenBSD `$2a$`
  vector must verify through the login path's own password check; a wrong
  password, a 71-byte prefix of a 72-byte password, and seven malformed
  stored values must not. Every other test hashes and verifies with one
  version, so none would notice a release that stopped reading old hashes.

## Not done

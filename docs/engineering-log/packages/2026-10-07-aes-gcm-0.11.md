# `aes-gcm` 0.10 → 0.11 (2026-10-07)

Backlog item, second of the encryption family
(`2026-10-06-major-version-backlog.md`). AES-256-GCM seals everything Talos
stores encrypted — secrets, actor memory, execution output, module
payloads, checkpoints, wrapped DEKs — and the secret envelope a job carries.

The algorithm did not change. What had to be shown is that a ciphertext
written before the bump opens after it, and a round trip through one version
of a library cannot show that.

## Pinned before the bump

Four tests, written and passing on 0.10 first, in which the real decrypt
path opens a ciphertext sealed OUTSIDE this code — by Python's
`cryptography`, under keys derived by RFC 5869 in Python, over made-up
inputs:

* a checkpoint, under the per-execution key (v2) and the legacy static key
  (v1) (`talos-engine`, `decrypt_checkpoint`);
* a secret envelope, under the per-job key (v2) and the v1 key
  (`talos-workflow-job-protocol`, `EncryptedSecrets`);
* a stored value in the `[nonce][ciphertext+tag]` layout
  (`talos-secrets-manager`, `aead_open_utf8`);
* a wrapped DEK, bound to its row and in the earlier unbound form
  (`EnvKekProvider::unwrap_dek`).

Each also asserts that the same ciphertext under another context is
refused: the tag still covers the AAD.

## Changed

* `aes-gcm = "0.11"`. The lockfile moves `aes-gcm`, `aes`, `ctr`, `ghash`
  and `polyval`, and gains `aead` 0.6, `universal-hash` 0.6 and `cpubits`.
* It compiled unchanged, with 36 deprecation warnings: `Nonce::from_slice`
  (and `Key::from_slice`), which also panics when given the wrong length.
  A nonce held as a `[u8; 12]` now converts infallibly. The six production
  sites that take a nonce out of stored or wire bytes use the checked
  conversion and return the error that function already returned for a
  malformed value. Every one of them had already checked or fixed the
  length, so no input is treated differently.

## Checked

On 0.11: the four tests above; the HKDF known answers from the previous
change; the whole of `talos-secrets-manager` and
`talos-workflow-job-protocol`; clippy; the unit suite; the DB-free binaries;
lint.

## Not done

* The envelope SEAL (X25519 key agreement, then AES-GCM) has no fixture
  here; it belongs with the `x25519-dalek` change.

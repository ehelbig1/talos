# `secrecy` 0.8 → 0.10 (2026-10-07)

First of the five the backlog table missed
(`2026-10-06-major-version-backlog.md`, "Closed out, and corrected"). One
crate declares it: `talos-dlp`, for `SecretValue`, the wrapper around a
credential found in a node's configuration so that it can be redacted from
that run's output and cannot be printed or serialized by accident.

## What changed in the library

`Secret<String>` is gone. A secret string is now `SecretString`, a boxed
`str` that is wiped when dropped.

The library's own conversion from a `String` calls `into_boxed_str`, which
first shrinks the buffer to the string's length. When the buffer has spare
capacity, a shrink may move the bytes and free the old block without wiping
it. 0.8 kept the `String` itself and wiped all of it, capacity included, so a
direct port would have weakened that for any caller that passes such a
string.

## Changed

* `SecretValue::new` copies the value into an allocation of exactly its
  length and then wipes the buffer it was handed, all of it, with `zeroize`
  (already in the workspace table). The one caller today passes an exact-size
  string, so this costs one small allocation per credential per run.
* `talos-dlp` declares `secrecy = "0.10"`. The lockfile loses `secrecy`
  0.8.0: `age` already brought 0.10.3, so the build now has one copy.

## Checked

* A test written first, on 0.8: a secret built from a string with spare
  capacity reads back whole and is redacted. It passes on both versions.
* The crate's 68 tests, and `talos-engine`'s (its sanitizer is the one
  consumer): 166 pass. Workspace clippy with warnings as errors.

## Stated limit

That the handed-in buffer is wiped is argued from the source, not tested: a
test would have to read memory after it has been freed.

# `md5` 0.7 → 0.8 (2026-10-06)

Backlog item (`2026-10-06-major-version-backlog.md`). One crate declares
`md5` and one line calls it: the `Md5` arm of the module `crypto::hash` host
function in `talos-worker-runtime/src/host/crypto.rs`.

* The call (`md5::compute(&data).to_vec()`) compiles unchanged against 0.8.1.
  The lockfile changes in one line.
* That arm had no test. `test_crypto_hash_known_answers` now drives the host
  function for all three algorithms against published vectors (RFC 1321 for
  MD5, the FIPS 180 "abc" vectors for SHA-256 and SHA-512), so a release that
  changed what a module is given would fail.

Not changed: MD5 stays offered to modules by the `crypto` interface, with the
existing WARN that it is broken. No catalog template calls it.

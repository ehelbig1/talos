# Lint checks 70, 52 and 64 do less work for the same verdicts (2026-10-05)

After check 14 and check 63, the three slowest structural checks were 70, 52
and 64. Each now skips work that cannot change its answer. No rule changed.

## Measured

Two trees, because two of the three costs depend on what is on disk. "Clean"
is a fresh worktree with no `target/`. "Build tree" is a copy of the tracked
files plus an empty-file copy of a real developer checkout's `target/` and
`frontend/node_modules/` (156,167 files, 19,589 directories). Walks cost the
same over empty files, and every check excludes these trees anyway.

| check | clean, before → after | build tree, before → after |
|---|---|---|
| 70 | 14.0 s → 2.1 s | 14.6 s → 2.3 s |
| 52 | 3.7 s → 0.5 s | 7.4 s → 0.9 s |
| 64 | 1.4 s → 1.5 s | 8.5 s → 1.5 s |
| whole lint | 80–82 s → 65–69 s | 106 s → 75 s |

Per-check times come from running the whole lint and timing the gap between
`▶ check N:` headers. The whole lint's output is unchanged: on the clean tree
it is byte-identical before and after (`✓ structural lints passed`), and on
the build-tree copy (which is not a git checkout, so some unrelated checks
fail there) old and new print the same 10 failures.

## Where the time went, and what changed

**Check 70** ran one `grep -rlE` per mapped table (24 today) over every `.rs`
file in `talos-*`, `controller` and `worker`, about 0.6 s each. Now:

1. one `grep -rlE 'UPDATE|DELETE|INTO'` over the same paths picks the files
   that can hold a write (338 of 1,068);
2. one perl read of those files lists the table names each contains, as a
   plain substring test (what `grep -lF <table>` would answer);
3. the unchanged per-table pattern runs only on that table's list.

Every match of the per-table pattern contains the table name and one of
UPDATE / DELETE / INTO literally, so a file dropped by steps 1–2 cannot
match. The walk is the same `grep -r` over the same paths, so files are found
and listed in the same order. If the perl read fails, the check prints
"could not read its candidate files — no verdict", fails the lint, and does
not print its green line. This was tested by making the perl `die`.

**Check 52** walked the whole tree twice with
`find . -not -path './target/*'`. That drops the files from the list but
still visits every directory under `target/`. Its third leg (`.try_get().ok()`)
also scanned every line of every `.rs` file character by character for `//`.
Now:

- the two `find`s `-prune` `./target` and `./node_modules`, the same two
  paths they filtered. They keep `"${TREE_PRUNE_FIND[@]}"`, which check 75
  requires;
- both perl passes skip a file that does not contain `try_get`. Both
  patterns contain `.try_get` literally, and the comment stripping before the
  third leg only deletes text;
- the comment scan skips a line with no `//`, which is the only thing it
  looks for.

**Check 64** calls `scripts/ci_test_targets.py` 12 times. Each call ran
`ROOT.rglob("tests")`, which walks into `target/` (and, from the main
checkout, into every agent worktree under `.claude/`) and drops those results
afterwards: 0.7–1.4 s per call. `tests_dirs()` now prunes `SKIP_DIRS` while
it walks. The CI runners use the same script, so they get faster too. The
check's shell code did not change.

## Equivalence: old and new code run on the same trees

For each check, the old block (extracted from `HEAD`) and the new block ran
under the same `set -euo pipefail` harness on the same tree. Their full
outputs were compared sorted, and also unsorted, which checks order too.
Every comparison below matched exactly in both forms.

| check | tree | violations, old / new |
|---|---|---|
| 70 | real tree | 0 / 0 |

For check 64, every classifier subcommand was compared: `check`, `list` and

Check 64's own output was also identical on the real tree and on the

## Found and left (not fixed here; each needs its own change)

- **Check 52c/d's comment scanner never handles a backslash escape.** Its
  test `if ($c eq "\\\\")` sits inside a bash single-quoted string, so perl
  compares one character against a two-backslash string and never matches.
  So a `\"` inside a string flips the in-string flag. A `.try_get(…).ok()`
  that follows `"a \" b // c"` on the same line is cut off as a comment and
  missed. This was shown on a one-file tree: the current check passes it, and
  a corrected test (`"\\"`) reports it. Population: the corrected scanner
  gives identical output on the real tree and on both altered copies, so 0
  real sites change verdict. A fix should be its own commit, with a planted
  case.
- **Check 52's legs do not agree on scope.** 52a (`grep -r
  --exclude-dir=target --exclude-dir=node_modules`) skips any directory with
  those names. 52b/c skip only the root `./target` and `./node_modules`. A
  `.rs` file in `frontend/node_modules/` or in a nested `target/` is checked
  by b/c but not by a, as copy B shows. Population today: 0 such files.
- **Check 70 only examines files that grep selects first.** That selection is
  case-sensitive and works one line at a time. The per-file perl is
  case-insensitive and its `\s+` crosses newlines. So a file whose only write
  on a table is lowercase, or has `INTO` and the table name on different
  lines, is never examined. To measure this, every file containing the table
  name in any case was passed to the perl: 0 violations on the real tree.
- **Check 64 aborts the whole lint when the classifier refuses the tree.**
  `ALL64="$(… python3 … list ungated)"` takes the exit status of that last
  call, which is 1 on a refused tree. `set -e` then stops the script inside
  check 64. Its ✗ lines are printed, but checks 65–97 never run and no
  summary line appears. The lint still exits non-zero, so the verdict is
  still a failure, but findings from the later checks are hidden. Old and new
  code behave the same here (shown on the 21-error copy).
- **`TREE_PRUNE_FIND` filters instead of pruning.** Its
  `-not -path '*/.claude/*'` still walks `.claude/`. All 12 `find .` scans
  that use it, run from the main checkout, therefore walk every agent
  worktree, build trees included. This is probably the largest remaining
  walk cost for a lint started there, but it was not measured: the session
  could not run commands outside its own worktree. Changing the shared list
  changes every scan that uses it, and check 75's rules about that list, so
  it was left.
- Check 70's per-(file, table) perl ends in `|| true`, so a crash there gives
  no hits instead of a failure. That code was not changed.

## Not done

- Calling the check 64 classifier once instead of 12 times. It would save
  about 1 s, which is below the bar for a rewrite.
- Check 70 still takes about 2 s, most of it the per-table `grep -E` over
  each table's own files. Getting it lower would mean replacing grep as the
  file selector, and that is exactly the part that keeps the result
  identical to the old one.

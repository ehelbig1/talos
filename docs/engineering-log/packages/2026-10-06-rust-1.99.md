# The Rust toolchain moves from 1.96 to 1.99 (2026-10-06)

## Measured

The pinned toolchain was 1.96 (1.96.1, released 2026-06-26), three stable
releases behind. 1.99.0 was released 2026-09-28, eight days before this
change, past the seven-day wait the repository's Dependabot config gives
any new release. GitHub's runner images had already moved their own
preinstalled toolchain to 1.99.0 (image 20261004).

The release is pinned in seven places: `rust-toolchain.toml`, the workspace
`rust-version`, `RUST_TOOLCHAIN` in `quality.yml` and `ci.yml`, and the rust
base image of `controller/Dockerfile` (twice), `worker/Dockerfile` and
`Dockerfile.builder` (twice). CI builds none of the three images, so a
Dockerfile left on the old release would have shown only at the next deploy.

## Changed

* All seven pins say 1.99. The base images are pinned by digest, read from
  the registry: `rust:1.99` (still Debian trixie, so the worker's
  `debian:trixie-slim` runtime stage still matches) and
  `rust:1.99-slim-bookworm`.
* Clippy under 1.99, workspace-wide with `-D warnings`, found eight sites,
  all fixed: a redundant borrow in `format!`, `truncate(0)` → `clear()`, a
  `for (_, v)` over a map → `.values()`, a `match` that is `?`, a
  `format!` with no arguments, an `assert!(a == b)` → `assert_eq!`, and
  two calls of `AtomicU64/AtomicUsize::fetch_update`, deprecated in 1.99 as a
  rename of `try_update` (same signature and semantics).
* `scripts/check-rust-pins.py`, run by `make lint`: it refuses a pin that
  disagrees with `rust-toolchain.toml`, a missing pin, a `stable` channel,
  and a rust base image without a digest. Its `--self-test` runs in the
  supply-chain job. `rust-toolchain.toml` lists the six other places.

## Verified

* `cargo fmt --check` and workspace clippy (`--all-targets -D warnings`)
  pass under 1.99.
* The four tools the Dockerfiles `cargo install` — sqlx-cli 0.8.6, wizer
  9.0.0, cargo-component 0.21.1, cargo-audit 0.22.2 — build with `--locked`
  under 1.99 (on macOS; the image build itself was not run).
* The unit tests of every touched crate pass under nextest, as CI runs them
  (2154 tests).

Not verified here: the three images. The operator's `make up` builds the
controller and worker images; `Dockerfile.builder` is built by the
publish workflow.

## Decided

* **`clippy::assert_is_empty` is allowed in the five engine crates** that
  enable `clippy::pedantic` (the lint is pedantic, so it fires nowhere
  else). It asks for `assert_eq!(v, [] as [T; 0])` in place of
  `assert!(v.is_empty())` — 47 test assertions there. Rewriting them is not
  part of moving a compiler; each crate's lint table says why.
* **`rust-version` moves with the toolchain**, as before: the workspace is
  built only with the pinned toolchain. (`try_update` itself already exists
  in 1.96; the tests above were also run there.)
* **The engine crates' own `rust-version = "1.88"` is left alone.** It was
  not in lockstep before and nothing builds them with another toolchain.

## Not done

* **A patch-level pin** (`1.99.0`). The convention is a minor pin, which
  takes 1.99.x patch releases; the Dockerfiles take them only when their
  digest is bumped.

## Found on the way (not changed here)

`cargo test -p talos-worker-runtime --lib` fails on a developer machine at
`the_send_path_refuses_a_name_that_resolves_private_where_upstream_connected`
— on 1.96 as well as 1.99. Other tests set `WORKER_ALLOW_PRIVATE_HOST_TARGETS=1`
for the whole process, so under plain `cargo test` the egress test can see the
opt-in. CI runs nextest (a process per test) and passes. Production ignores
the variable. Proposed as its own task.

## A warning 1.99 now prints

Cargo reports that `proc-macro-error2` 2.0.1 "contains code that will be
rejected by a future version of Rust" (it re-exports the private
`proc_macro` crate, E0365). It is a build-time dependency of `age` (through
`i18n-embed-fl`), which only `talos-offhost-backup` uses, and it is already
recorded as unmaintained (RUSTSEC-2026-0173 in `deny.toml`). Nothing fails
today. The toolchain bump that turns it into an error will need `age` to
have moved off it, or the backup tool to use another implementation.

## Cost, once

The build cache key includes the toolchain, so the first CI run of each job
after this change compiles every dependency.

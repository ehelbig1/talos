# `cap-std` 3.4 → 4.0 (2026-10-06)

Backlog item (`2026-10-06-major-version-backlog.md`). `cap-std` is the
library the `files` host functions go through: a module's read, write, list
and delete are resolved beneath its sandbox directory, whatever the path
says.

## Measured

* Two crates use it (`talos-worker-runtime`, `talos-workflow-engine`).
  `controller` declared it and called it nowhere; that declaration is removed.
* `wasmtime-wasi` 49 already depends on `cap-primitives` 4.0.3, so the tree
  carried the library's core twice. The bump removes `cap-primitives` 3.4.6
  and `io-extras` 0.18.4 and adds only `cap-std` 4.0.3: one copy, the one
  wasmtime uses.
* No code change was needed; both crates compile unchanged.

## The test that was missing

Every existing path-traversal test (`..`, an absolute path, an embedded
`..`, for read, write and delete) is refused by `sanitize_path`, which looks
at the path's text, before `cap-std` is asked anything. So nothing tested
what the library itself guards, and a release of it could not have failed a
test.

`a_symlink_out_of_the_sandbox_is_not_followed`
(`worker/tests/sandbox_security_tests.rs`) plants a file symlink and a
directory symlink inside a module's sandbox, both leading to a file outside
it. Two controls first: an ordinary file in the sandbox reads back, and with
ambient authority both links do read the outside file. Then, through the
host functions, a read and a write through either link are refused, and
after a delete through each the outside file is unchanged.

## Verified

`sandbox_security_tests` 40 pass; `talos-worker-runtime` and
`talos-workflow-engine` 1,325 tests pass under nextest; clippy `-D warnings`
on the four crates and `make lint` pass.

Stated limit: the symlink test is `cfg(unix)` and was run on macOS; CI runs
it on Linux, where the library uses a different mechanism (`openat2`).

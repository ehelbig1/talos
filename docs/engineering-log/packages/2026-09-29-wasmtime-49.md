# 2026-09-29 — Wasmtime 48.0.3 → 49.0.1

**Why.** Wasmtime backported RUSTSEC-2026-0313…0316 only to 36.0.16 (LTS) and
48.0.3. 48 stops receiving security backports once 50 ships, and 49 needs
Rust 1.96, which #982 delivered. 49.0.1 is the latest 49.x.

**The API: no source change.** The workspace compiles on 49.0.1 as it did on 48.
The review therefore went to behaviour, through the checklist in
`docs/wasmtime-version-tracking.md`:

| Surface (48.0.3 vs 49.0.1) | Finding | Action |
|---|---|---|
| `Config::features()` (the default feature set) | **`WIDE_ARITHMETIC` is now ON by default** | pinned off |
| `wasm_*` knobs, `Config` methods, pooling-allocator knobs | identical | none |
| `default_operator_cost` | identical | none |
| `VariableOperatorCost` defaults | **`memory_grow_per_page` 0 → 1** | kept, and pinned explicitly |
| `wasmtime-wasi-http` hook contract (`ctx.rs`, `p2/*`, errors, options) | byte-identical | none; the gated handler and its between-bytes bound hold |
| `wasmtime-wasi` sockets | a polling refactor; `SocketAddrUse` checks at the same 17 call sites | none |
| `wasmtime-wasi` filesystem primitives | restructured | see limits |

**Decided.**
- **Wide arithmetic is pinned OFF** (`config.wasm_wide_arithmetic(false)`, in the
  fingerprint and in check 20's required list). It is the case the lockdown
  exists for: a proposal turning on by default silently widens the Cranelift
  codegen surface. Check 20 alone would not have caught it; it verifies a fixed
  list of opt-outs. Measured before deciding:
  - rustc's `wasm32-wasip2` target does not enable `wide-arithmetic`, and the
    compilation service passes no target-feature flags;
  - all **115** installed modules (14.2 MB) validate without it
    (`wasm-tools validate --features wasm3,component-model`);
  - control: a module using `i64.add128` is rejected without the feature and
    accepted with it.
- **`memory.grow` now costs 1 fuel per 64 KiB page**, on top of the fixed 255.
  Upstream closed a gap: it was the one variable-size operation charging nothing
  per unit. Kept, because charging real work is the stronger bound and the cost
  is negligible: a whole module memory is at most a few thousand fuel, against
  budgets in the millions. Pinned explicitly in `OperatorCost.variable` and the
  fingerprint, so a future default change is a visible diff.
- **AOT:** the version macro reads 49.0.1, the fingerprint is re-pinned, and the
  header is `TALOSV10`, so V9 blobs are rejected and recompile on first use. The
  header grew from 7 to 8 bytes. An old `TALOSV1` blob whose HMAC begins with
  `0` would pass the header comparison but still fail HMAC verification, which
  is the actual boundary. At worst it is refused with an HMAC error rather than
  a version error.

**Proof.**
- New tests on the PRODUCTION engine (`TalosRuntime::new()`):
  - `the_production_engine_refuses_locked_down_proposals`: an ordinary module
    compiles; SIMD (control) and `i64.add128` are refused;
  - `memory_grow_is_charged_per_page_on_the_production_engine`: growing 16 pages
    costs exactly 16 fuel more than growing 0.
- **Mutations: 3 applied, 3 caught:** wide arithmetic not pinned; per-page back
  to 0; SIMD lockdown removed (the control).
- **Suites:**
  - 1 000 passed across `talos-worker-runtime` and `worker` (1 pre-existing
    skip), including the `wasi:http` gate, SSRF, body-hardening and
    files-API path-traversal tests;
  - 919 across the other runtime consumers and `talos-local-inference`;
  - the controller binary's 93.
- `cargo deny check advisories` against the live database: ok. The workspace
  check (all targets), clippy `-D warnings` and `make lint` are clean.

**Stated limits.**
- **`wasi:filesystem` path containment is not tested by Talos.** The primitives
  were restructured in 49. Talos's own path-traversal tests cover its `files`
  host functions; raw `wasi:filesystem` containment inside a preopen is
  upstream's sandbox, covered by upstream's filesystem test suite. Talos grants
  a preopen only to the filesystem and trusted worlds, on a per-execution temp
  directory.
- **One-time recompile:** AOT blobs recompile on first use after deploy.
- **Next:** 49 stops receiving backports when 51 ships. The monthly cadence in
  the tracking doc stands.

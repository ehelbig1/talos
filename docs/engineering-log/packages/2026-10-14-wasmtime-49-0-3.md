# Wasmtime 49.0.2 → 49.0.3 (2026-10-14)

**Why.** The RustSec database gained fifteen advisories against 49.0.2 on
2026-10-14 (RUSTSEC-2026-0350…0364). `cargo-deny` failed on `main` from #1300's
merge and on every open pull request (first seen on #1301, which touches no
wasmtime code). 49.0.3 is the patched release on the line we run.

Two of them are not panics:

- **RUSTSEC-2026-0350**: a guest can send an absolute-form `wasi:http`
  request to a host other than the one it named, which bypasses the host
  admission that `wasi:http` sends pass through (security review E-9 gave
  that path its caps in #1300).
- **RUSTSEC-2026-0352**: a filesystem sandbox escape when renaming symlinks
  whose paths end in a slash.

The rest are a long-URL `wasi:http` host crash (0351), ten component-model
host panics (0353…0362), handle tables that are capped only per instance
(0363) and unaligned exception tags (0364).

**What changed.**
- The three workspace pins (`wasmtime`, `wasmtime-wasi`, `wasmtime-wasi-http`)
  are now 49.0.3, and the lockfile moved the whole family. No API changed.
- `wasmtime_version!` is 49.0.3, so the boot log and the AOT fingerprint
  report it.
- The fingerprint hash is re-pinned (only its wasmtime line changed).
- `AOT_VERSION_HDR` is now `TALOSV12`, so a TALOSV11 blob is refused by its
  header and recompiled on next use, rather than failing its HMAC.
- `docs/wasmtime-version-tracking.md` is updated (current pin and history).

**Run.**
- `make audit`: advisories, bans, licenses and sources ok.
- `make lint`.
- `cargo clippy -p talos-worker-runtime -p worker --all-targets -- -D warnings`.
- `cargo test -p talos-worker-runtime -p worker`: all pass, including
  `fingerprint_wasmtime_version_matches_cargo_toml` and
  `engine_config_fingerprint_is_pinned`.
- `cargo build --profile docker --bin worker` and `--bin controller`.

**Deploy.** The worker image carries the fix. Cached AOT blobs are recompiled
once on first use after the roll, so expect a one-time compile latency per
module.

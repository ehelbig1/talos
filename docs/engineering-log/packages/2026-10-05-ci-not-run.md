# A CI run that never ran is not a broken main (2026-10-05)

`module-templates/github-workflow-run` v1.3.0 reports a new state, `not_run`.

## Why

During GitHub's Actions incident of 2026-10-05 (runners not handed out;
GitHub's own annotation: "The job was not acquired by Runner of type hosted
even after multiple attempts"), two runs of `quality.yml` on main concluded
`failure` although every job that ran passed:

* run 37360981472 (#1105): 13 jobs green; only `Quality gate` never got a
  runner and was cancelled — the run concluded `failure`.
* run 37372976097 (#1106): `Changed areas` and `Supply-chain` never got a
  runner; `Quality gate` ran and failed *because of them*.

`talos-ci-watch` read both as a broken main and sent "CI failed on main".

## What the reader does now

Only when the chosen run concluded `failure`, it reads that run's jobs
(`/actions/runs/<id>/jobs?filter=latest&per_page=100`, one more GET to the
host it already has). Measured on both runs: a job that never started is
`cancelled` with no steps and no runner. The run is `not_run` when at least
one job never started and no job failed except `GATE_JOB` — the aggregator
that fails because others did not succeed. A job cancelled after it started
(steps present) counts as a failure. `not_run` leaves the rolling ops alert
alone and carries `jobs_not_run`.

## Decided

* **The gate is named, not guessed.** Nothing in the API marks a job as an
  aggregator; the run 37372976097 gate's failure looks like any other job's.
  Without `GATE_JOB` that run stays `failing` (the gate-never-started shape
  needs no name: nothing that ran failed).
* **An unreadable or incomplete jobs listing keeps the run `failing`**, with
  `jobs_read: false` in the output and a WARN. A false alarm is better than a
  hidden real failure.
* **No consumer change.** The private `ci-watch` compose already skips any
  state other than `failing` and `passing` and leaves its memory alone, so a
  `not_run` is silent and the next real verdict is compared with the last one.
* **Deliberately NOT done:** falling back to the next older conclusive run.
  It would cost a jobs read per skipped candidate and report an older run's
  verdict as the newest.

## Measured

`make check-catalog-fuel`: 7 863 126 fuel against the declared 15 825 000
(49.7%) with a failed run and its 14-job listing (≈40 KB) — the worst case;
was 6.75M with the runs listing alone. `bytes_per_item` 13000 → 14500. The
fixture's newest main run was `success` although its README said `failure`;
it is now `failure`, so the check exercises both requests.
